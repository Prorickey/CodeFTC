# Connecting Cameras

Vision is one of the most powerful tools available to FTC teams. With a camera, your robot can locate scoring targets, read AprilTag positions, and navigate the field without relying on dead reckoning alone. This lesson covers the hardware setup and the FTC SDK's **VisionPortal** API that sits at the center of all camera-based code.

## Supported Cameras

FTC supports two categories of cameras:

**USB Webcams**
Any UVC-compatible USB webcam works. Popular choices include:
- Logitech C270 (~$25) — inexpensive, wide field of view
- Logitech C920 (~$60) — higher resolution, better low-light
- Microsoft LifeCam HD-3000 (~$30) — good color accuracy

Plug the webcam into a USB-A port on the Control Hub. The Control Hub has two USB ports; use the blue USB 3.0 port for best bandwidth.

**Built-in Camera (Android Phone)**
If you are using an Android phone as the Robot Controller, the phone's rear camera can also be used. Phone cameras are generally less repeatable to aim and harder to mount rigidly.

For new teams, a USB webcam on a Control Hub is the recommended setup.

## Configuring the Camera in Robot Config

Before your code can access the camera, you must add it to the robot configuration file on the Driver Station app:

1. Open the Driver Station app → hamburger menu → **Configure Robot**
2. Tap **New Configuration** (or edit an existing one)
3. Tap your Control Hub → **USB Webcam**
4. Tap the webcam entry and set its name — use `"Webcam 1"` (this is the name you will use in `hardwareMap.get()`)
5. Save and activate the configuration

The name you assign here must exactly match what you type in your Java code.

## The VisionPortal

The FTC SDK's `VisionPortal` class is the single entry point for all camera-based vision. It:
- Opens the camera and manages the frame stream
- Routes each frame to one or more **vision processors** you attach
- Handles lifecycle (start, stop, close) cleanly

You build a `VisionPortal` with its fluent `Builder`:

```java
import org.firstinspires.ftc.vision.VisionPortal;
import org.firstinspires.ftc.vision.apriltag.AprilTagProcessor;
import com.qualcomm.robotcore.hardware.WebcamName;

// Build the processor(s) first
AprilTagProcessor aprilTag = new AprilTagProcessor.Builder()
        .setDrawTagOutline(true)
        .build();

// Then build the portal
VisionPortal portal = new VisionPortal.Builder()
        .setCamera(hardwareMap.get(WebcamName.class, "Webcam 1"))
        .addProcessor(aprilTag)
        .setCameraResolution(640, 480)
        .build();
```

The portal starts streaming immediately once `build()` returns. Frames flow into the processors automatically in the background.

## Camera Resolution and Performance

The resolution you choose affects both accuracy and processing speed:

| Resolution | FPS (typical) | Use case |
|---|---|---|
| 320×240 | 30+ | Fast detection, less precision |
| 640×480 | 20–30 | Best balance for FTC (recommended) |
| 1280×720 | 10–20 | High precision, more CPU load |

Always use the lowest resolution that still meets your accuracy needs. High resolutions can slow down detection and consume Control Hub CPU.

## Checking the Portal State

After building the portal you can check whether it is live:

```java
VisionPortal.PortalState state = portal.getPortalState();

if (state == VisionPortal.PortalState.RUNNING) {
    telemetry.addLine("Camera is streaming");
} else {
    telemetry.addLine("Camera not ready: " + state);
}
telemetry.update();
```

Possible states: `RUNNING`, `STOPPED`, `CAMERA_DEVICE_CLOSED`, `ERROR`.

## Pausing and Closing the Portal

To save CPU during the `init` phase, pause streaming and resume it when the OpMode starts:

```java
// In init():
portal.stopStreaming();

// In runOpMode() after waitForStart():
portal.resumeStreaming();
```

Always close the portal when you are done to free the camera for the next OpMode:

```java
// At the end of runOpMode():
portal.close();
```

Failing to close the portal can prevent the camera from opening in the next run.

## Putting It Together

```java
@Autonomous(name = "Camera Setup")
public class CameraSetup extends LinearOpMode {
    @Override
    public void runOpMode() {
        AprilTagProcessor aprilTag = new AprilTagProcessor.Builder().build();

        VisionPortal portal = new VisionPortal.Builder()
                .setCamera(hardwareMap.get(WebcamName.class, "Webcam 1"))
                .addProcessor(aprilTag)
                .setCameraResolution(640, 480)
                .build();

        telemetry.addData("Portal state", portal.getPortalState());
        telemetry.update();

        waitForStart();

        // Vision processing happens automatically in background threads
        while (opModeIsActive()) {
            telemetry.addData("Portal state", portal.getPortalState());
            telemetry.addData("Detections", aprilTag.getDetectionCount());
            telemetry.update();
        }

        portal.close();
    }
}
```
